Filter Editor

Build filters with nested rules, write them as text, preview how many messages they match, and share them as files.

Overview

The filter bar is good for quick filters: a few bubbles combined with and, or and not. The filter editor is for everything else: groups inside groups, regular expressions on any field, number and type comparisons, time ranges, conditions you switch off without deleting, and filters that reuse other saved filters.

The window has three parts:

  • The builder (left): the filter as rows you click and pick from.
  • The predicate text (right): the same filter written in the predicate language that log stream --predicate and Xcode's console use. Edit either side; the other follows.
  • The bottom bar: a live count of matching messages, then Cancel, Apply and Save.

Opening the editor

  • In the filter bar, open the … menu and choose Edit.
  • Or right-click any bubble and choose Edit in Filter Editor.

Each device (your Mac, a simulator, a phone, an opened log file) has its own editor window. Opening it again brings the existing window to the front. The editor starts from the filter the device is using now, including edits you made in the bar that aren't saved yet.

The window title shows the filter's name, followed by (Edited) when the editor holds changes that aren't saved.

The builder

Groups

Every filter is a group. A group's menu says how its members combine:

GroupMatches a message whenWritten as
All ofevery member matchesA AND B
Any ofat least one member matchesA OR B
None ofno member matchesNOT (A OR B)
Not all ofat least one member doesn't matchNOT (A AND B)

Groups can hold other groups. Each nesting level gets its own coloured edge so you can see where a group starts and ends. Filters can be nested up to 32 levels deep.

Rows

A group holds three kinds of rows:

  • Conditions: a checkbox, a field, a match type and a value, for example Subsystem starts with com.apple..
  • Groups, nested inside this one.
  • Saved filter links: “Matches saved filter Name ▾”. See Saved filter links.

Use the buttons at the bottom of each group to add a row to it: ＋ Condition, ＋ Group and ＋ Saved filter.

Switching a condition off

Untick a condition's checkbox to switch it off without deleting it. It's dimmed and struck through, and the filter behaves as if it weren't there. Tick it again to bring it back. In the text, a switched-off condition is a line starting with //.

Moving, duplicating and deleting

  • Drag a row by its handle ≡ onto another row to put it there, or onto a group's add buttons to move it to the end of that group.
  • The ⋯ menu on each row has Duplicate, Delete, Wrap in Group, Move Up and Move Down.
  • A group's ⋯ menu has Delete, Ungroup (its members move up into the parent) and the Move commands; ⧉ duplicates the whole group.

Invalid values

A value the field can't use, such as a regular expression that doesn't compile or a PID that isn't a number, turns red. Hover over it to see why. A red condition is ignored until you fix it, so it never silently hides messages.

Match types

[c] means “ignore case”.

A regex must match the whole value. This is how log and Xcode treat MATCHES. To find a word anywhere in a message, surround it with .*: .*timeout.* matches “Request timeout after 30s”, while timeout alone only matches a message that is exactly “timeout”.

Numbers and Type

PID, Thread ID, Activity ID and Type can be compared: is, <, ≤, >, ≥ or a regex. For Type, ≤ and ≥ read at most and at least, and follow log's order:

Default → Info → Debug → Error → Fault

So Type at least Error keeps errors and faults, and Type at most Info keeps default and info messages.

Time of day

Matches messages logged between two wall-clock times, on any day. Times are HH:mm or HH:mm:ss.

  • The end time includes all of it: 09:00–09:15 keeps everything up to 09:15:59.999, and 21:45:30–21:46:00 keeps everything up to 21:46:00.999.
  • A range can cross midnight: 22:00–02:00 keeps the late evening and the early morning.

The predicate text

The right side shows the filter as text, in the predicate language Apple's tools use. Type there and the builder follows about a third of a second after you stop.

process ==[c] "DuckDuckGo"
AND (messageType >= error
     OR eventMessage MATCHES[c] ".*time(d)? ?out.*")
AND NOT subsystem BEGINSWITH[c] "com.apple."
// AND category ==[c] "networking"
AND timeOfDay BETWEEN {"09:00", "18:00"}

The language

  • Combine with AND, OR and NOT (or &&, ||, !), and group with parentheses.
  • Compare with ==, !=, <, <=, >, >=, CONTAINS, BEGINSWITH, ENDSWITH, MATCHES and BETWEEN.
  • Values go in double quotes. Numbers and Type names (error) can be written without quotes.
  • A line starting with // is a switched-off condition.
  • TRUEPREDICATE matches every message (an empty filter).

Moving between the two sides

Click a row in the builder and its text is highlighted. Click in the text and the row written there is selected in the builder. Press ⌘F in the text to find.

When the text has an error

While the text doesn't parse, the error is shown in red under it, and the builder is locked and shows the last version that worked. Fix the text and the builder catches up. Apply, Save, Export and Copy wait until the error is fixed.

Using the text with log and Xcode

The note under the text says whether the filter works as it is with log stream --predicate and in Xcode's console. Parts only BetterConsole understands are highlighted:

  • Time of day and Extra data conditions
  • Saved filter links (filter == "Name")
  • Regular expressions on PID, Thread ID, Activity ID or Type
  • Event types log doesn't know
  • Switched-off conditions, and conditions with an invalid value

When there are highlighted parts, Copy as log predicate copies the text without them, ready to paste into Terminal:

log stream --predicate 'process ==[c] "DuckDuckGo" AND messageType >= error'

Saved filter links

＋ Saved filter adds a row that matches whatever another saved filter matches. In the text it's written filter == "Name".

  • Links are live. Change the linked filter later and every filter that links it follows. Build a “Noise” filter once, then add None of → Matches saved filter Noise wherever you need it.
  • Deleted filters. If the linked filter is deleted, the row shows a red Missing filter and is ignored until you choose another one. Deleting a filter that others link asks first and names them.
  • No loops. A filter can't include itself, directly or through other filters. The editor marks the row and Save refuses with “This would make ‘Name’ include itself”.

Preview, Apply and Save

Live preview

The bottom bar shows Would match N of M messages on Device, counted in the background over the messages the device has stored. It updates shortly after every change, and every couple of seconds while the window is in front, as new messages arrive.

Cancel, Apply and Save

ButtonWhat it does
Cancel escCloses the editor. If there are changes, it asks first; Keep Editing is the default.
ApplyUses the filter on the device now, without saving it. The filter bar shows “(Edited)”. The editor stays open so you can keep refining.
SaveApplies, then saves into the device's saved filter. If the device has no saved filter yet (Untitled), it asks for a name.

Changes from the filter bar

If you change the same device's filter in the filter bar while the editor holds its own changes, a yellow banner appears: Reload takes the bar's version, Keep my version keeps the editor's.

Import and export

Export…

Saves the filter to a file you can keep in a repository or send to a colleague. Pick a format in the save panel:

  • Predicate text (.bcfilter, the default): the same text as the editor, with a short header. Readable, diff-friendly, and pasteable into log.
  • JSON (.json): the filter as a tree, for scripts and tools.

Filters it links are written into the same file, so it works on another Mac.

// BetterConsole filter
// version: 1
// name: DDG Errors
process ==[c] "DuckDuckGo"
AND messageType >= error
AND NOT filter == "Noise"

// filter: Noise
subsystem BEGINSWITH[c] "com.apple."

Import…

Replaces what's in the editor with a filter from a file: .bcfilter, .json, .txt, or a file without an extension. Nothing is applied or saved until you press Apply or Save, and ⌘Z brings back what you had.

  • A plain text file holding just a predicate works too, for example one copied from a log stream --predicate command.
  • Linked filters are matched by name with your saved filters. Any that aren't found are listed, and their rows show Missing filter until you choose one.

The filter bar's … menu also has Import and Export, for adding files straight to your saved filters.

Undo and redo

  • ⌘Z and ⇧⌘Z, or the ↶ ↷ toolbar buttons, undo and redo every change, from the builder, the text or an import.
  • Typing a value counts as one step, not one per letter.
  • The history starts again after Save.

Recipes

Errors from my app, except one noisy category

process ==[c] "MyApp"
AND messageType >= error
AND NOT category ==[c] "analytics"

Two processes, one subsystem each

Builder: Any of containing two All of groups.

(process ==[c] "MyApp" AND subsystem ==[c] "com.example.sync")
OR (process ==[c] "MyWidget" AND subsystem ==[c] "com.example.widget")

HTTP status codes 4xx and 5xx in the message

eventMessage MATCHES[c] ".*status[ =:]+[45][0-9]{2}.*"

Everything during a test run window

process ==[c] "MyApp" AND timeOfDay BETWEEN {"14:02:10", "14:03:00"}

Messages from processes in a folder

processImagePath BEGINSWITH[c] "/Applications/MyApp.app/"

Try a condition without losing it

Untick it. The preview count shows the difference at once; tick it again to bring it back.
